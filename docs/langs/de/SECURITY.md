# Sicherheit

[Русский](../../../.github/SECURITY.md) | [English](../en/SECURITY.md) | [Español](../es/SECURITY.md) | [中文](../zh/SECURITY.md) | [Français](../fr/SECURITY.md) | **Deutsch**

Diese Richtlinie gilt für die aktuelle stabile Version und den aktuellen master; frühere Versionen werden nicht separat gepflegt. Das Werkzeug läuft lokal mit den Rechten des aufrufenden Benutzers und ändert Namen im ausgewählten Ordner. Verwenden Sie vertrauenswürdige Verzeichnisbäume, Sicherungen und die erforderlichen minimalen Rechte. Bearbeiten Sie keine Daten, die andere Prozesse gerade ändern. Ein transaktionales Rückgängigmachen oder Schutz vor beliebigen gleichzeitigen Änderungen wird nicht versprochen.

## Schwachstelle melden

Veröffentlichen Sie keine Schwachstellendetails in Issues oder Discussions. Nutzen Sie GitHub Security → Report a vulnerability, sofern verfügbar. Ist kein privater Kanal verfügbar, veröffentlichen Sie keine Details; bitten Sie den Maintainer ohne technische Einzelheiten um einen sicheren Kontaktweg. Nennen Sie Version, Betriebssystem und Shell, ein minimales synthetisches Beispiel, erwartetes und tatsächliches Verhalten, Auswirkungen und bereinigte Protokolle. Stimmen Sie die Offenlegung nach der Behebung ab.
