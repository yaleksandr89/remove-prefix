Cette politique couvre la version stable actuelle et master actuel ; les versions antérieures ne sont pas maintenues séparément. L’utilitaire s’exécute localement avec les droits de l’utilisateur et modifie les noms dans le dossier choisi. Utilisez des arborescences fiables, des sauvegardes et les privilèges minimaux. Ne traitez pas de données modifiées par d’autres processus. Aucun retour arrière transactionnel ni protection contre les modifications concurrentes arbitraires n’est promis.

## Signaler une vulnérabilité

Ne publiez pas de détails de vulnérabilité dans Issues ou Discussions. Utilisez GitHub Security → Report a vulnerability lorsque cette option est disponible. À défaut de canal privé, ne divulguez pas de détails publiquement ; demandez au responsable un moyen de contact sécurisé sans détails techniques. Indiquez la version, le système et le shell, un exemple synthétique minimal, le comportement attendu et réel, l’impact et des journaux expurgés. Coordonnez la divulgation après correction.
